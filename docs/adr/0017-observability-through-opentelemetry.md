# 17. Observability through OpenTelemetry, configured by the standard OTEL_* variables

Status: accepted

## Context

Operators want to follow requests and ship goldie's logs into their existing observability stack (#13, #77). The platform contract says every variable uses the GOLDIE_ prefix, that settings come from the registry in internal/platform/settings.go, and that every setting is validated at startup (PC-04). OpenTelemetry defines its own variable names (OTEL_*), which collectors, operators and Helm charts already use, and its Go SDK reads several of them by itself. Until now goldie depended on about 20 modules. The OTLP exporters bring in protobuf and, through the generated collector packages, the gRPC runtime, even for HTTP-only export. That roughly doubles the stripped binary (9.2 MB to 18.2 MB) and raises the module count to about 100.

## Decision

Goldie emits telemetry with the OpenTelemetry Go SDK, from internal/platform only, and installs no global tracer, meter or log provider. Metrics are served by one MeterProvider held by the platform Telemetry (Meter), with an explicit cardinality limit of 2000 data points per instrument, so a caller-controlled attribute cannot grow memory without bound. Export is OTLP over http/protobuf only; gRPC exporters are not added. Telemetry is configured by the standard OTEL_* variables, which are the one exception to the GOLDIE_ prefix. Telemetry is off unless an OTLP endpoint or an exporter variable turns it on, and OTEL_SDK_DISABLED=true always turns it off. Goldie validates and documents the variables that select and address the exporters: OTEL_SDK_DISABLED, OTEL_EXPORTER_OTLP_{,TRACES_,LOGS_,METRICS_}{ENDPOINT,PROTOCOL,HEADERS}, OTEL_{TRACES,LOGS,METRICS}_EXPORTER, OTEL_METRIC_EXPORT_INTERVAL, OTEL_EXPORTER_OTLP_METRICS_TEMPORALITY_PREFERENCE, OTEL_SERVICE_NAME, OTEL_RESOURCE_ATTRIBUTES, OTEL_TRACES_SAMPLER{,_ARG} and the span limit variables, each read through the injected lookup and passed to the SDK explicitly. These fail fast naming the variable (PC-04), and the HEADERS variables accept a _FILE form (PC-05); for the other names a _FILE form is an error, because the SDK would ignore it. Other OTEL_* variables the SDK reads, such as batch tuning, timeouts, TLS and compression, keep the SDK's own semantics and are not validated by goldie, but the SDK's own logger and error handler are replaced by goldie's, so a value it rejects is never printed: one fixed warning is logged instead. Startup logs the enabled signals, the protocol and each collector as scheme://host only. The configuration reference says so. On the server only the public listener is traced; the admin port never is. The client roles (the client commands and goldie mcp over stdio) export traces only, never logs or metrics, and the logs and metrics variables and GOLDIE_TELEMETRY_CLIENT_INFO do not apply to them. Each API call is one client span, sent to the server as a W3C traceparent (TraceContext only, no baggage). The server does not join the caller trace: it starts its own and links its span to the client span (#13), so a client cannot place spans in the server trace or steer its sampling. A client span carries no header, query string, userinfo or article id (route template only). A resource attribute goldie.role names the process: server on the server, cli or mcp on the client roles. goldie.mode stays a server-mode concept (all today; api, ui and mcp after #24) and is not set on a client, so a stdio client is never mistaken for a server mode in operators' dashboards. The SDK notices of a client go to stderr, and a client flushes for at most 2 seconds on exit. No OpenTelemetry type leaves internal/platform. Logs keep the PC-07 stdout shape and are also bridged to OTLP at the same level. Any goldie-owned telemetry setting keeps the GOLDIE_ prefix. platform-contract.md gains a telemetry clause (PC-12) stating this.

## Consequences

Operators configure goldie like any other OpenTelemetry workload, and the variable names become part of goldie's operator interface, so they are hard to rename. PC-04's fail-fast promise is narrowed for telemetry: a mistyped batch, timeout, TLS or compression variable falls back to the SDK default without failing startup. The sampler and span limit variables fail fast, and a negative span limit, which the SDK reads as unlimited, is refused. Every role pays the cost of the dependency in binary size and module count, as ADR 0001 implies; the client roles export traces when OTEL_* selects them, and an unreachable collector delays their exit by at most 2 seconds. The metrics provider adds go.opentelemetry.io/otel/sdk/metric and the otlpmetrichttp exporter. Each upgrade of the OTel v0 modules (log exporter, metrics exporter, otelhttp, otelslog) can break their APIs, and the gRPC and protobuf modules must be kept free of known vulnerabilities even though goldie never speaks gRPC. Dropping the gRPC runtime would need a hand-written OTLP/HTTP encoder or an upstream split of the proto module.
